# lib/

This folder holds local copies of the DLLs the build needs, **not committed
to git** (see `.gitignore`). They all come from a real installation of the
game with BepInEx installed — never from the "dummy" DLLs generated by
Il2CppInspectorRedux, which cannot be invoked at runtime and are only good
for reading the code statically in `BW_export/il2cpp.cs`.

On this machine the game is installed at:
```
F:\SteamLibrary\steamapps\common\Big Walk\
```
with BepInEx already initialized (build `6.0.0-be.781`, runtime `.NET 6.0.7`,
IL2CPP — see `BepInEx\LogOutput.log` in that folder to confirm).
**Important**: launch through Steam (`steam://run/1478500`) rather than
running the executable directly — confirmed in session on 2026-09-15 that a
direct launch does not load BepInEx on this machine (nothing at all in
`LogOutput.log`). There is also a copy of the game in `F:\Games\Big Walk\`,
never launched through Steam, which is not the one to deploy to.

## The DLLs currently copied here

From `<game>\BepInEx\core\` (step 1):
- `BepInEx.Core.dll`
- `BepInEx.Unity.IL2CPP.dll`
- `0Harmony.dll`

From `<game>\BepInEx\interop\` (generated by Il2CppInterop on the first
launch — NOT the dummy DLLs):
- `Assembly-CSharp.dll` (step 2) — the game's own types (`SaveablePropName`,
  `RewardGourd`, `Prop`, `SaveManager`, ...)
- `Mirror.dll` (step 3) — `NetworkBehaviour`, the base of `RewardGourd`/`Prop`
- `UnityEngine.CoreModule.dll` (step 3) — `MonoBehaviour`, the base of
  `NetworkBehaviour`
- `Il2Cppmscorlib.dll` (step 3) — `Il2CppSystem.Object`, the base of
  `UnityEngine.Object`
- `Unity.TextMeshPro.dll` (step 4, 2026-09-15) — `TMP_InputField`
  (`HostMenuConfirm.gameNameField`/`passwordField`), for
  `Debug/DebugMenuLookup.cs`
- `UnityEngine.UI.dll` (step 4, 2026-09-15) — `Selectable`, the base class of
  `TMP_InputField`
- `UnityEngine.IMGUIModule.dll` (step 5, 2026-09-15) — `OnGUI`/`GUI.Label`,
  for the on-screen Archipelago status (`Core/Net/ApStatusOverlay.cs`)
- `Mirror.Transports.dll` (step 6, 2026-09-25) — `KcpTransport`,
  `MultiplexTransport`, `EosTransport`, for the loopback guest
  (`Debug/DebugNetworkLookup.cs`). Copied from the Steam install's
  `BepInEx\interop\`

From `<game>\BepInEx\core\` (step 3):
- `Il2CppInterop.Runtime.dll` — `Il2CppObjectBase`, the base of
  `Il2CppSystem.Object`

That chain of dependencies (`Object` → `Il2CppSystem.Object` →
`Il2CppObjectBase`, `MonoBehaviour` → `NetworkBehaviour` →
`Prop`/`RewardGourd`) is typical of IL2CPP interop: referencing one of the
game's types forces you to reference its whole base-class hierarchy up to
`Il2CppObjectBase`, each link in its own DLL.

**Important**: `<Nullable>disable</Nullable>` in the csproj is not cosmetic.
These interop DLLs carry their own incomplete
`System.Runtime.CompilerServices.NullableAttribute` — missing some of its
constructors — which fails the build (CS0656) as soon as one of them is
referenced with Nullable Reference Types on.

## If you change machine, or the game updates

Copy the DLLs out of the game's `BepInEx/` folder **after** launching the
game at least once with BepInEx installed — that first launch is what
generates `BepInEx/interop/` through Il2CppInterop. A different game version
can change a method signature, so rebuild after a game update.
